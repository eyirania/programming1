# 선생님 코드 반영 및 검증

대상: `1_숙직.cpp` (81행). 원본의 바이트를 보존하고 SHA-256을 기록했다. 세 풀이가 한 파일에 이어 붙여져 있어 각각 분리해 컴파일했다. 문서의 주석은 학습 자료로만 사용했다.

| 풀이 | 원본 행 | 추가 헤더 | 검증 사례 |
|---|---|---|---:|
| #1 back | 1–22 | 없음, stdio.h만 사용 | 166 |
| #2 queue | 24–52 | queue | 169 |
| #3 dt-for | 54–80 | algorithm | 169 |

504회 모두 별도 참조 알고리즘의 최소 단계 결과와 일치했다. 양의 이동 거리, 1≤a≤b<1200을 검사했다. #1은 조합 수가 빠르게 커지므로 작은 거리 차이만 검사했다. 큰 입력에서도 빠르다고 주장하지 않는다. 세 main을 함께 컴파일할 수 없다는 것은 예제를 묶은 자료 형식의 특성이며 풀이 오류로 분류하지 않았다.

## 앱의 코드 스타일 정정

- 60개 코드 문제와 연결된 코드 패턴 20개를 모두 `stdio.h`와 `printf` 중심으로 다시 작성했다.
- C만 사용하는 40개는 C11로, 수업의 STL이 필요한 20개는 C++11로 컴파일했다. 실제 코드는 고급 C++ 문법을 학습 조건으로 요구하지 않는다.
- `iostream`, `cout`, `cin`, `auto`, 람다, 범위 기반 for, `std::string`, 불필요한 헤더 묶음을 제거했다.
- 일반 배열, 격자, 동적표는 고정 크기 배열로 바꿨다. 문자열 처리는 char 배열을 사용한다.
- `vector`는 강의의 인접리스트/자료구조 문제에만, `queue`·`stack`은 해당 자료구조 문제에만 사용한다.
- `algorithm`은 PDF에 있는 sort/lower_bound/upper_bound와 선생님의 min 사용에만 남겼다. 코드마다 헤더의 이유를 접어서 읽을 수 있다.
- DFS 정점 번호순은 인접행렬의 번호 순 반복, 입력순은 vector의 첨자 반복으로 명시했다. 관련 복잡도 설명도 수정했다.
- 숙직 Q082–Q084는 #3의 변수 a, b, able, dt와 계산 구조를 따른다. 출력 추적을 위해 scanf 입력만 주어진 초기값으로 대체했다. 원본 코드의 54–80행을 출처로 연결했다.
- 함수 호출 횟수 문제는 반환값을 먼저 저장한 다음 printf로 출력한다. `printf("%d %d", f(n), cnt)`처럼 인수 평가 순서에 의존하는 변환을 피했다.

## 원본을 읽을 때의 조건

- `dt[1200]`은 0–1199 인덱스만 유효하다. 프로그램의 배열 크기와 별도로 실제 문제의 입력 조건을 따라야 한다.
- queue 풀이에서 dt=0을 미방문 표식으로 써도 시작점의 거리 0과 충돌하지 않는 이유는 모든 이동이 양수여서 시작점으로 돌아가지 않기 때문이다. 임의의 순환 그래프에 그대로 적용하는 일반 규칙은 아니다.
- back의 `ans<cnt` 가지치기는 원본에서 주석 처리되어 있다. 활성화된 것처럼 설명하지 않았다.
- 성공한 뒤 추가 호출은 목표를 넘어가 종료한다. 양의 이동거리 가정이 필수이며 0/음수 이동까지 임의 확장하지 않는다.
- 동적표의 99999는 도달 불가능 표시다. 주어진 배열 크기에서 가능한 최소 단계 수보다 충분히 크다.
